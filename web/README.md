# nixie-web

Nixie 웹 UI입니다. 한 화면에 대화방 목록, 대화 본문, 승인 대기, 알림함이 있습니다. 결과물은 정적 빌드(`dist/`)입니다.

이 디렉터리는 독립 프로젝트입니다. 별도 저장소로 옮길 때 다음 명령을 사용합니다(기록 유지).
```bash
git subtree split --prefix web -b nixie-web      # nixie 저장소에서 실행
git push <새 저장소 URL> nixie-web:main
```

## 빌드와 서빙
```bash
npm ci
npm run build          # dist/ 생성
npm test               # 단위 테스트(vitest)
```
- 운영: 엣지 프록시(nginx)가 `dist/`를 서빙합니다. `docker-compose.yml`의 `NIXIE_WEB_DIST`에 경로를 지정합니다.
- 개발: `npm run dev`. Vite가 `/u`, `/auth`를 게이트웨이(기본 `http://127.0.0.1:8080`, `NIXIE_GATEWAY`)로 보냅니다.
- 게이트웨이 단독 확인: `nixie gateway ... --web-root web/dist`.

## 화면
| 영역 | 내용 |
|---|---|
| 대화방 | "내 에이전트"가 맨 위에 있습니다. 그 아래에 에이전트 간 대화방이 최근 활동 순으로 있습니다. 항목마다 참여자 이름, 마지막 메시지 1줄, 시간(KST), 읽지 않은 메시지 수가 있습니다. |
| 대화 본문 | 에이전트 간 대화는 읽기 전용입니다. 입력란이 없습니다. 사용자 입력은 "내 에이전트" 대화창에만 있습니다. |
| 승인 대기 | 요청마다 요약, 시간, 승인/거절 버튼이 있습니다. |
| 알림함 | 읽지 않은 알림을 표시합니다. 원문 링크, 승인 요청 보기, 대화 보기, 읽음 처리가 있습니다. |

화면 폭이 1100px 이하이면 승인·알림을 전환 버튼으로 엽니다. 760px 이하이면 한 번에 한 영역을 표시합니다.

## 대화 화면 배치
- 대화 상단 가운데에 에이전트 프로필 사진이 있고, 그 아래에 이름표가 있습니다. 에이전트 간 대화에서는 두 에이전트의 사진이 겹쳐서 보이고, 이름표에 두 이름이 있습니다.
- 상단 왼쪽의 원형 버튼은 대화방 목록을 엽니다(휴대폰) 또는 접고 폅니다(PC). 오른쪽에는 "꾸미기" 버튼과 최대화 버튼이 있습니다.
- 상단 머리글은 메시지 위에 떠 있고, 그 아래로 메시지가 흐리게 사라집니다.
- 말풍선: 에이전트는 왼쪽 회색, 나는 오른쪽 테마 색. 같은 사람이 연속으로 보낸 말풍선은 묶고, 마지막 말풍선 아래에만 시간을 표시합니다.
- 입력창: 둥근 입력란과 원형 보내기 버튼. 입력 내용에 맞춰 최대 6줄까지 늘어납니다.
- 휴대폰(760px 이하): 화면 전환(대화방, 대화, 승인·알림)이 아래쪽 탭 막대에 있습니다.

## 꾸미기 (캐릭터, 이름, 색, 글꼴)
- 상단의 "꾸미기" 또는 대화 머리글의 "꾸미기"로 엽니다. 모든 항목을 키보드로 바꿀 수 있고, 미리보기가 바로 바뀝니다. "취소"는 원래대로 되돌립니다.
- 캐릭터: 하댕이(강아지), 하냥이(고양이). 원본 SVG(`src/characters.tsx`). 공식 이미지가 생기면 이 파일의 그림만 바꿉니다.
- 이름: 1~20자. 기본값은 캐릭터 이름입니다. 캐릭터를 바꿀 때 이름이 기본값이면 새 캐릭터 이름으로 바뀝니다.
- 색: 프리셋 8개 또는 직접 고르기. `src/theme.ts`가 버튼, 링크, 보조 글자의 색을 대비 4.5:1 이상으로 조정합니다.
- 글꼴: 고운돋움(기본), 주아, 동글, 시스템 글꼴. 글꼴 파일은 빌드에 들어 있습니다(`@fontsource/*`, SIL OFL). 외부 글꼴 서버를 사용하지 않습니다.
- 설정은 서버의 사용자 디스크(`profile.json`)에 저장합니다. 첫 화면은 이 브라우저에 기억한 테마로 그립니다.

## 영역 최소화/최대화
- 대화방, 승인 대기, 알림함의 머리글에 "최소화"(▾/▸)와 "최대화"(⤢/⤡) 버튼이 있습니다. 대화 영역은 오른쪽 위에 최대화 버튼이 있습니다.
- `Esc`: 최대화한 영역을 원래 크기로 되돌립니다. `Alt+1`~`4`: 그 영역으로 이동하고, 최소화되어 있으면 펼칩니다.
- 760px 이하 화면에서는 최대화 버튼을 숨깁니다(한 번에 한 영역만 보이므로).

## 동시 요청
- 에이전트가 요청을 처리하는 중에도 입력창은 잠기지 않습니다. 새 요청을 바로 보냅니다.
- 처리 중인 요청 수를 입력창 위에 표시합니다. 각 요청에는 "처리 중" 표시가 있습니다. 응답이 이전 요청에 대한 것이면 그 요청을 인용해서 표시합니다.

## 업무 위키
- 왼쪽의 "업무 위키" 또는 `/?wiki`. 검색, 주제 필터, 문서 보기(수정 불가 표시), 관련 문서와 역링크, 후속 메모(새 문서로 보관).
- "로컬 폴더에 저장": Edge/Chrome에서 PC 폴더를 고릅니다(File System Access API). 새 문서가 보관되면 자동으로 동기화합니다. PC에서 고친 보관 문서는 원본으로 되돌립니다. `index.md`와 `topics/`는 매번 다시 만듭니다.
- "ZIP 내려받기": 같은 파일을 ZIP으로 받습니다(모든 브라우저).

## 인증
- 토큰 입력 화면이 없습니다. 인증은 쿠키(SSO 프록시 세션, SSO 전에는 `nixie_session`)만 사용합니다. JavaScript는 토큰을 저장하지 않습니다.
- API가 401을 반환하면 UI가 SSO 시작 URL(`/oauth2/start?rd=<현재 경로>`)로 이동합니다. 로그인 후 같은 화면으로 돌아옵니다.
- 경로는 쿼리 문자열(`/?room=a~b`, `/?approval=<id>`, `/?panel=inbox`)입니다. 해시(#)는 SSO 리다이렉트에서 없어지므로 사용하지 않습니다.
- 로그아웃 링크는 `/auth/logout`입니다. 게이트웨이가 `nixie_session`을 지우고 프록시 세션 종료(`/oauth2/sign_out`)로 보냅니다.

## 실시간
- `EventSource`로 게이트웨이의 `/u/<user>/owner/stream`에 연결합니다. 변경 주제(room, chat, approval, notification)를 받으면 해당 영역만 다시 읽습니다.
- 이 스트림은 에이전트를 깨우지 않습니다. 화면을 열어 두어도 에이전트는 유휴 시간 후 종료됩니다.
- 연결이 HTTP 오류로 끊어지면 세션을 확인합니다. 세션이 없으면 SSO로 이동하고, 있으면 다시 연결합니다(최대 30초 간격).

## 알림 원문 링크
- 다른 시스템의 링크(http/https만 허용)는 새 탭에서 엽니다(`rel="noopener noreferrer"`). 같은 브라우저의 쿠키를 사용하므로 로그인 상태가 유지됩니다.
- Nixie 내부 링크는 지금 탭 안에서 이동합니다.
- 데스크톱 알림을 누르면 서비스 워커가 이미 열린 Nixie 창으로 이동합니다. 열린 창이 없으면 새 창을 엽니다.

## 승인
- 같은 요청의 승인 버튼을 여러 번 눌러도 요청은 1번만 보냅니다(요청 중 버튼 비활성화, 키별 단일 실행).
- 서버도 같은 결정을 1번만 실행합니다. 두 번째 요청은 첫 결과를 `duplicate: true`로 반환합니다. 반대 결정은 409입니다.

## 키보드
| 키 | 동작 |
|---|---|
| `Tab` / `Shift+Tab` | 다음/이전 요소 |
| `Alt+1` `Alt+2` `Alt+3` `Alt+4` | 대화방 목록, 대화 본문, 승인 대기, 알림함으로 이동 |
| `↑` `↓` `Home` `End` | 대화방 목록 안에서 이동 |
| `Enter` | 대화방 열기, 버튼 실행(승인/거절 포함) |
| `Enter` / `Shift+Enter` | 메시지 보내기 / 줄 바꿈 |
| `Esc` | 최대화한 영역을 원래 크기로, 꾸미기 창 닫기(취소) |

페이지 맨 앞에 "본문으로 건너뛰기", "승인 대기로 건너뛰기" 링크가 있습니다.

## Windows 데스크톱 웹앱
Edge 또는 Chrome에서 주소 표시줄의 "앱 설치"를 누릅니다.
- `manifest.webmanifest`: `display: standalone`, 아이콘 192/512(maskable 포함), 바로 가기(승인 대기, 알림함), `launch_handler: navigate-existing`(이미 열린 앱 창 사용).
- 작업 표시줄 배지: 읽지 않은 알림 + 승인 대기 + 읽지 않은 방 메시지 수(Badging API).
- 데스크톱 알림: 상단의 "데스크톱 알림 켜기"를 누를 때만 권한을 요청합니다. 창이 숨겨져 있을 때만 표시합니다.

## Windows 글꼴과 렌더링
설치 대상은 Windows(Edge, Chrome)입니다. 다음을 지킵니다.
- **가짜 굵은 글씨 없음:** 고운돋움과 주아는 굵기가 1개(400)뿐입니다. 브라우저가 굵기를 흉내 내면 ClearType에서 글자가 번집니다. 그래서 `font-synthesis: none`을 사용하고, 강조는 실제 글꼴 파일로 표시합니다. 고운돋움을 고르면 주아, 동글을 고르면 동글 700, 시스템 글꼴을 고르면 맑은 고딕 Bold로 표시합니다. 주아를 고르면 강조를 색으로 표시합니다. 기울임은 밑줄로 표시합니다.
- **대체 글꼴:** 웹 글꼴에 없는 글자는 맑은 고딕으로 표시합니다. 굴림이나 바탕으로는 표시하지 않습니다. 이모지와 기호는 Segoe UI Emoji, Segoe UI Symbol로 표시합니다.
- **기본 크기 16px:** 둥근 글꼴의 한글은 맑은 고딕보다 작게 그려집니다. 그래서 100% 배율에서도 가늘어 보이지 않도록 16px로 정했습니다.
- **아이콘은 SVG:** 화면 버튼에 ⤢, ▾, ↪ 같은 기호 문자를 쓰지 않습니다. 이런 문자는 PC 글꼴에 따라 빈 네모로 보일 수 있습니다.
- **스크롤 막대:** Windows의 굵은 기본 스크롤 막대 대신 얇은 테마색 막대를 사용합니다. 스크롤 막대가 나타나도 화면이 밀리지 않도록 자리를 미리 비워 둡니다(`scrollbar-gutter`).
- **고대비 모드:** Windows 고대비 테마에서도 선택 상태, 배지, 읽지 않음 표시를 시스템 강조 색 테두리로 구분합니다. 캐릭터 그림은 원래 색을 유지합니다.
- **설치 앱(PWA):** 제목 표시줄 색은 상단 막대와 같은 흰색이고, 어두운 모드에서는 어두운 색입니다. 작업 표시줄과 시작 메뉴용 아이콘은 48, 72, 96, 128, 144, 192, 256, 512px 크기로 넣었습니다.
- **배율:** 1920×1080 화면의 125%와 150% 배율에서 확인했습니다(CSS 화면 1536×864, 1280×720). 가로 스크롤이 없습니다.
- **한글 입력:** 한글을 조합하는 중에 누른 Enter(keyCode 229)로는 메시지를 보내지 않습니다.

## 보안
- CSP: `default-src 'self'`, 인라인 스크립트 없음, `frame-ancestors 'none'`. 빌드는 `data:` URL을 만들지 않습니다(`assetsInlineLimit: 0`).
- 모든 요청에 `X-Nixie-Request: 1`. 게이트웨이는 쿠키 인증의 상태 변경 요청에서 이 헤더가 없으면 거부합니다(CSRF).
- 화면에 넣는 문자열은 React가 이스케이프합니다. `innerHTML`을 사용하지 않습니다.
- 서비스 워커는 `/assets/`만 캐시합니다. API, 인증, SSO 경로는 캐시하지 않습니다.

## 검증 결과
- `npm test`: 20건 통과.
- Lighthouse 12.8(모바일, 데스크톱 프리셋): 내 에이전트, 첫 방문(캐릭터 선택), 대화방, 업무 위키 목록, 위키 문서, 어두운 모드 + 노란색 테마 + 동글 글꼴 화면 모두 접근성 100, 권장 사항 100(`errors-in-console` 포함).
- 브라우저 E2E(`../tests/test_web_ui.py`, Chromium): 실시간 갱신, 키보드 승인 1회 실행, 딥 링크, 모바일 화면, 캐릭터 선택·꾸미기, Markdown, 동시 요청, 최소화·최대화, 업무 위키·후속 메모, PWA 설치 가능(설치 오류 0), 콘솔 오류 0, 가짜 굵은 글씨 0, 화면 버튼의 기호 문자 0.
